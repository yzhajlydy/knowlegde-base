1. 熵”指的是一个系统混乱的程度，或者说是无序程度的度量——越无序，熵的值就越大；越有序，熵的值就越小；而热力学第二定律说：在一个封闭的系统内，事物总是从有序趋向于无序，所以熵的值一定是增加的。这就是“熵增定律”
2. 一个公司股票背后本质的价值，是它能产生的自由现金流。一家公司的此刻的价值，应该等于它未来能够产生的所有的现金流的价值
3. 会议时间成本 = 每人时间成本 x 参会人数 x 会议时间。提高开会效率就需要尽可能减少会议时间成本。比如精简与会人数，明确议题等
4. 好的系统应该有三个特点：
5. 第一，它要有抗打击能力。一成不变的系统反而是脆弱的。一个具备抗打击能力的系统得能经得起扰动，取得一个动态的平衡
6. 第二，它要有自组织能力。系统内的每个成员自己创新
7. 第三，它应该有一个健康的层级结构。各个子系统在相当程度上是自治，这就不会有点什么事都搅动整个系统
8. 评估担责：谁对业绩结果负责，谁就有权用人；谁对业绩结果作评价，谁就应该对评价结果负责
9. 业绩评估，不是目的，而是手段。是要寻找进一步改善业绩的途径和办法，把未来的业绩做得更好，是为了更好地调整队伍，带出一支更优秀的队伍。业绩评价，不是为了评价，而是为了带人
10. 婚姻三阶段：
11. 制度化阶段：婚姻主要满足的是我们最基本的需求，比如说提供住所、提供食物，帮助我们免于外界的侵害
12. 陪伴式阶段：夫妻们更多关注的是那些中层次的需求，比如说，爱、被爱、体验浪漫的激情
13. 个人化阶段：人们想在婚姻中追求的是他们比较高层次的需求，比如说自我实现、表达自我，或者说是获得尊重等
14. 我们应该学会的是如何成功经营自己的单身生活。我一直觉得爱情在当代社会被过分强调了，越是依赖越是相爱，失去的时候就越痛苦。即使白头偕老，最后的最后还是要一个人离世，或者一个人独自活着……与其强调如何获得爱情，更紧迫地是应该学习如何独处。单身一样生活，并不是要我们过一种与世隔绝的生活，而是说我们应该学会享受独处的时光，能够和那些与我们能够互相帮助、沟通、理解的人建立很紧密的朋友关系。这不仅会让你，而且也会让你的亲密关系都从中受益
15. 高效执行的几个关键要素：个体动力（能力 x 意愿） x 协作水平 （默契 x 机制）x 方向有效性 （目标 x 沟通）x 时长
16. 个体动力（能力 x 意愿）：每位成员的个体能力和努力的意愿
17. 协作水平（默契 x 机制）： 成员间的组织结构是否合理，协作的节奏是否一致
18. 目标清晰度（目标 x 沟通）：大家是否在朝着一个稳定的目标努力
19. 关于年轻入职新人培养思路上，给与管理者的几点建议：
20. 给任务的时候一定要明确
21. 要善于定好小目标，这是方法层面的建议。要善于把大目标分解成中目标和小目标。目标越小，评价周期越短，效果会越好
22. 给年轻人即时反馈
23. 不要吝啬鼓励
24. 奖励一个人需要在公开场合，而批评或指出问题需要在一对一的时候，这样效果才好
25. 认知不协调。我们身边常常有这种现象，比如你买了一只股票，因为你买了这支股票，你看这支股票的眼光就不客观了，你总是希望它涨，因为你希望它涨，所以你就不能用理性的心态去考虑什么时候把它卖掉
26. 关于犯错文化：
27. 在企业里培养允许犯错的企业文化，把批评变为“建议+鼓励”
28. 定义算术错误，和高数错误。允许犯创新带来的高数错误，不允许犯粗心带来的算术错误
29. 向上管理，就是一种向对你有管理权力的人，施加影响力的方法论。给上司提问题的三点建议：
30. 不只是提问题，同时也要提出建议

35. 谷歌的绩效考核方式是：360度环评。你周围的人，包括你直属经理都会给你打分，最后加权算出一个得分。其实不仅谷歌，包括微软，以及发明OKR的英特尔都是这样。通过多人打分，让直属经理一个人的主观，接近多人评价的客观；通过更高级别组织对得分的再平衡，让小团队的主观，接近多团队均衡的客观
36. 管理销售团队，流水线车间，能用KPI，千万别用OKR。KPI是秒表，OKR是指南针
37. 实施OKR的四个关键：
38. 目标要有野心，关键结果要可衡量。既然不考核，设立目标时，应鼓励大家挑战极限
39. 最多5个目标，每个目标最多4个关键结果。
40. 目标从公司，到团队，到个人层层分解。从上到下的OKR，总体上是包含关系。下级也可自定义OKR，但要与大方向一致
41. 所有OKR公开，透明。大家要知道彼此在干什么，确保方向一致，也给目标过低、结果过差的员工压力
42. 技术管理者在做技术决策时需要考量的几个关键指标：
43. 结果评估。即值不值得做，投入是什么，收益是什么，做成什么样子
44. 可行性评估。即能不能做，从技术角度分析技术方案的可行性
45. 维护评估。技术做成之后，需要考虑如何维护，用尽可能少的资源维护尽可能多的工作
46. 几种典型的管理风格：没有哪一种风格是好的，无所谓对与错，在不同场景下需要不同的管理风格。如工作不容有闪失，严格按照要求来执行，则适合指令式管理；团队需要凝聚力和斗志，需要攻坚时，则适合支持式管理；核心人才需要重点培养，建立团队梯队时，则适合教练式管理；团队比较成熟，成员需要发挥自己的空间时，适合授权式管理
47. 指令式管理：重事不重人，关注目标和结果，喜欢发号施令但不亲力亲为
48. 支持式管理：重人不重事，喜欢带头冲锋亲力亲为，特别在意团队成员的感受，并替他们分担工作
49. 教练式管理：重人也重事，关注全局和方向，并在做事上给与教练式辅导和启发
50. 授权式管理：不重人也不重事，关注布标和结果，不关心过程和人员发展
51. 没有绝对正确的管理方法，只有针对某个时期，合适的管理方法。因为管理是为了解决实际问题的，而在不同场合下，环境输入变量千差万别，做出的管理决策拿到统一坐标轴下对标甚至有可能是相互冲突的。

81. 提升激励效果的三个原则
82. 具体。对他所做的事情要具体，明确是因为什么而受到的奖励

85. 技术管理者需要做的两个决策：
86. 优先级决策。即决定什么是重要的，优先做什么。优先级的决策取决于组织目标。可以从判断什么事不该做开始入手：丝丝入扣、设计完美的大系统先不要做；功能的精益求精不要做（主要矛盾）
87. 扩展性决策。组织扩展（调整组织架构）；人员扩展（人才储备给目标服务）；技术扩展（能否支撑未来的技术要求）
88. 管理的三明治结构：
89. 前提是角色认识。
90. 中间是管理规划（目标）、团队建设（分工、激励、梯队等）、任务管理（流程、执行）
91. 最后是管理沟通。
92. 项目有效执行的四个要素：
93. 目标清晰。目标是否明确、是否传达、变更是否同步
94. 责任不明。明确唯一的责任人、各合作方的负责人是否明确、总负责人和各分负责人是否达成共识
95. 推进不力。没有机制保证、机制虽有，没有人检查、机制虽多，没有抓住关键环节
96. 沟通不畅。沟通是否主动、沟通是否达成一致、沟通是否闭环
97. 保证流程和机制的可执行性，需要遵循几个原则。另外注意两点：流程和机制不是越多越好，而是越少越好。因为涉及到维护成本
98. 可操作，简单原则。尽量简单，不要设计的太复杂
99. 只打关键节点，即关键原则。
100. 明确到人，即问责原则。
101. 从case中来，到case中去，即实用原则。
